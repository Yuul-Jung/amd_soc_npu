먼저 05절 회귀 시뮬레이션이 모두 통과해야 합니다. Vivado가 설치된 PC의 VS Code 터미널에서 진행하며, 단계 하나라도 실패하면 다음 단계로 넘어가지 않습니다.

8-1. 합성·구현·타이밍 (VS Code 터미널)

Ubuntu Terminal · Vivado 배치 (저장소 루트)
source /tools/Xilinx/Vivado/<버전>/settings64.sh   # 설치 경로에 맞게 변경
vivado -mode batch -nojournal -source mini_npu/scripts/vivado_impl.tcl
# 마지막 줄 기대: SYNTH_TIMING_PASS ch12 basys3_npu_top WNS=… WHS=… DRC_ERRORS=0 LUT=… FF=… DSP48E1=… RAMB=…
판정 항목기준확인 위치
SetupWNS ≥ 0 (TNS = 0)mini_npu/build/impl/timing_route.rpt
HoldWHS ≥ 0 (THS = 0)같은 파일
DRCError 0drc_route.rpt
자원DSP48E1 ≥ 4 (MAC 레인 4개) — 기대값, 실행 전 ⚠ 미검증util_route.rpt

생성물(mini_npu/build/impl/): basys3_npu_top.bit, post_route.dcp(GUI 확인: File → Checkpoint → Open), 타이밍 시뮬레이션용 basys3_npu_top_timesim.v·.sdf. SYNTH_TIMING_FAIL이면 다음 단계로 넘어가지 않습니다.

8-2. 배선 후 타이밍 시뮬레이션 (xsim + SDF)

Ubuntu Terminal · 8-1 성공 후
bash mini_npu/scripts/run_timing_sim.sh
# 기대 마지막 3줄:
# INTEGRATED_UART_RTL_SIM_PASS classes=6 model_edit=1 invalid_length=1
# PC_GOLDEN_COMPARE_PASS predictions=6 model_edit=1
# TIMING_SIM_PASS ch12 basys3_npu_top post-route SDF(slow) classes=6 model_edit=1 invalid_length=1

05절과 같은 tb_npu_uart.sv를 배선 후 넷리스트(slow corner 지연)에 연결합니다. 넷리스트에도 uart_rx가 있으므로 스크립트가 TB의 UART 수신 모니터만 tb_uart_rx_monitor로 이름을 바꾼 사본(mini_npu/build/timesim/)을 씁니다. 원본 TB는 수정하지 않습니다. 약 30 ms 분량의 UART 통신을 게이트 수준으로 시뮬레이션하므로 RTL 시뮬레이션보다 훨씬 오래 걸립니다(소요 시간 ⚠ 미측정).

8-3. 한 번에 실행하고 증거 저장

Ubuntu Terminal · 00~10장 OOC + 12장 구현 + 타이밍 시뮬레이션
bash tools/run_vivado_all.sh
# 기대 마지막 줄: VIVADO_ALL_PASS (all)
# 저장: ch00~ch10/validation/vivado_ooc_YYYYMMDD.txt
#       ch12/validation/vivado_impl_timesim_YYYYMMDD.txt  (WNS/WHS · bit sha256 · 타이밍 시뮬레이션 결과)

저장된 증거 파일을 커밋하면 각 장의 SYNTH_TIMING_PASS(12장은 TIMING_SIM_PASS 포함)가 확정됩니다. 아래 8-4 이후는 실물 보드가 준비된 경우에만 진행합니다(현재 ⚠ 미실시).

8-4. 보드 프로그래밍 (보드 준비 시)

  1. Basys3 점퍼 JP1을 JTAG로 두고, micro-USB(PROG/UART 겸용)를 PC에 연결한 뒤 전원 스위치를 ON합니다.
  2. Vivado Open Hardware Manager → Open Target → Auto Connect → xc7a35t_0 확인.
  3. Program Device → Bitstream file에 mini_npu/build/impl/basys3_npu_top.bit 선택 → Program. DONE LED가 켜집니다.

8-5. UART 터미널 연결

Ubuntu Terminal · 115200 8N1, 흐름 제어 없음
ls -l /dev/serial/by-id/            # Digilent ...-if01-port0 → ttyUSBn 이 UART
sudo apt install -y picocom
picocom -b 115200 -d 8 -p n -y n -f n /dev/ttyUSB1   # n은 실제 번호로 변경 · 종료 Ctrl-A Ctrl-X

8-6. 시험 입력과 판정

문자 키 하나를 누르면 1바이트가 전송됩니다. Enter의 CR/LF는 무시됩니다. 응답은 C+클래스+:+점수 4개(41비트 signed, 11자리 16진수)+CRLF입니다.

입력기대 UART 응답LEDFND
0C0:00000000002,00000000000,00000000000,FFFFFFFFFFELED0 켜짐 · LED14 켜짐오른쪽 끝 자리 0 (나머지 세 자리 0)
1C1:00000000000,00000000002,FFFFFFFFFFE,00000000000LED1 켜짐 · LED14 켜짐오른쪽 끝 자리 1 (나머지 세 자리 0)
2C2:00000000000,FFFFFFFFFFE,00000000002,00000000000LED2 켜짐 · LED14 켜짐오른쪽 끝 자리 2 (나머지 세 자리 0)
3C3:FFFFFFFFFFE,00000000000,00000000000,00000000002LED3 켜짐 · LED14 켜짐오른쪽 끝 자리 3 (나머지 세 자리 0)
SI변화 없음변화 없음
ZERRLED15 켜짐 (오류 래치)변화 없음
BTNC응답 없음LED14·LED15 꺼짐, LED0 켜짐오른쪽 끝 자리 0

LED 할당(npu_display_controller.v): LED0~3 = 클래스 one-hot, LED13 = BUSY, LED14 = DONE 래치, LED15 = 오류 래치(NPU·명령·UART framing·overrun). LED4~12는 꺼져 있습니다. BTNC는 리셋입니다.

주의X·W·B·R은 뒤에 바이너리 바이트가 따라와야 하므로 터미널 키 입력으로 시험하지 않습니다. 잘못 눌러 응답이 멈추면 BTNC로 리셋합니다.
